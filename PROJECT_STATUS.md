## Behavior verified by source inspection

Source paths refer to the pinned revision. Acceptance, static inspection, and runtime verification are separate.

- **Import and playback.** [`audio.py`](backend/app/audio.py) and [`main.py`](backend/app/main.py) accept little-endian RIFF/WAVE 16/24-bit integer PCM, including supported extensible PCM with matching container/valid widths and block alignment. Float, 32-bit integer and other codecs are outside the accepted implementation. The defaults are 500 MiB and 900 seconds. The upload is hashed as it streams, stored unchanged in `blobs/{sha256}`, and deduplicated. SQLite persists projects/assets/jobs. Range playback uses the 16-bit master or a cached triangular-dither 16-bit derivative for 24-bit input. Derivative failure leaves the master intact and playback unavailable. Navigation uses `playback_minmax_envelope_v1`, separate from T01. Fixture scope is described below.
- **Analysis and cache.** [`main.py`](backend/app/main.py), [`worker.py`](backend/app/worker.py), and [`pipeline.py`](backend/app/pipeline.py) implement HTTP 202, a separate local worker, retry after interrupted work, and reuse of a completed run for the asset, `m1-v3`, and parameter hash when `metrics.json` exists. The file cache lives under `analysis/{sha256}/m1-v3/`. The worker reads the master, not the playback derivative. A chart failure is isolated. PNG failures can leave ready data with a caveat and no image. The job type permits `canceled`, but no cancellation route or transition is present in the inspected source.
- **Technical evidence.** [`measure.py`](backend/app/measure.py), [`charts.py`](backend/app/charts.py), [`png.py`](backend/app/png.py), and the [ECharts renderer](frontend/src/chart.tsx) show T01 levels/waveform and peak marker, T02 FFmpeg EBU R128 loudness and RMS, T03 Welch spectrum, T04 STFT and band traces, T05 stereo/mono compatibility, T06 pulse candidates, T07 pitch-class/key candidates, T08 spectral change, T09 within-file spectral-shape recurrence, and T10 ending/gap/rail/reconstructed-peak checkpoints. Ready T01–T05 and T10 use `measured`. Mono T05 is `not_available` / `not_applicable`. T06–T09 use `estimated`. Technical charts and their PNGs share chart documents. Time-based charts and timestamped marker controls seek the shared transport. Chart zoom is local to chart axes. Chart presentation and contract gaps are tracked in the [decision register](docs/OPEN_DECISIONS_AND_UNCERTAINTIES.md).
- **Lyric evidence.** [`lyrics.py`](backend/app/lyrics.py), [`main.py`](backend/app/main.py), and the [lyric workspace](frontend/src/lyrics.tsx) implement `.txt`, `.md`, and `.srt` uploads (1 MiB limit), original lyric-byte storage, revisioned edits, usable waveform regions, notes, explicit manual confirmation, and HTTP 409 stale-write rejection. Text/Markdown begin unplaced. SRT uses supplied cue times and preserves validation issues. A manual confirmation records an artist action. Lyric edits do not invalidate the technical cache. The project evidence read combines existing signal evidence, lyric observations, and separately attributed annotations. [`lyric_charts.py`](backend/app/lyric_charts.py) and [`lyric-charts.tsx`](frontend/src/lyric-charts.tsx) build L01–L05 on read from stored T02, T08, and T09 plus the current lyric document. They do not write the technical cache.
- **Frontend and offline operation.** [`App.tsx`](frontend/src/App.tsx) and [`analyzer.tsx`](frontend/src/analyzer.tsx) show a library, an asset-specific analyzer, an Album QC empty state, and AI disabled in Settings. The published source uses one recording transport across Technical Analysis and Lyrics & Inspiration. Accepted frontend presentation and the responsive-width rule are in the [Pass 2 record](docs/design/studio-precision.md). Technical measurements and current chart artifacts run locally.
